Pondra is one program that takes in streams of rows, stores them as tables in a folder or a bucket
(Parquet files plus a small catalog), and answers SQL. Materialized views, keyed tables and event-time
windows keep results current as rows arrive, and other engines can read the tables as Delta Lake or
Iceberg. Object storage is the only state, so there is no Kafka, Flink, Spark, JVM or metastore to run:
start another copy on the same bucket and it joins the first.

## One binary replaces

For the common jobs, `pondra` takes the place of a stack:

| Instead of running | For | Pondra has |
|---|---|---|
| **Kafka** | Ingesting events, topics, consumers | `append` with exactly-once batches, and a Kafka port: producers, consumers and Debezium change events |
| **Flink** | Streaming SQL: windows, joins, deduplication | Materialized views, event-time windows, stream joins, `ASOF JOIN` and tasks |
| **Spark** | Batch SQL, ELT and DataFrames | SQL that can spread over several nodes, `pondra.frame`, and PySpark's names in `pondra.spark` |
| **A metastore** (Hive, Polaris, Unity) | The catalog of tables | A catalog inside the bucket, and an Iceberg REST catalog on every node |
| **ZooKeeper** | Picking a leader | A leader elected through the bucket |

It is a prototype, and it replaces them for the common jobs, not all of them.
[Pondra compared](/pondra/concepts/compared/) says where Spark, Flink, Fluss, DuckDB, Databricks and
Snowflake are stronger.

## Try it in 30 seconds

Install Pondra with pip (other ways are on the [install page](/pondra/start/install/)), and start the
shell on a folder called `lake`:

```bash norun
pip install pondra
pondra
```

Then type SQL. This makes a table and a view that keeps its totals current, writes three rows, and
reads the totals:

```sql
CREATE TABLE events (user VARCHAR, amount BIGINT);
CREATE MATERIALIZED VIEW totals AS SELECT user, sum(amount) AS total FROM events GROUP BY user;
INSERT INTO events VALUES ('ann', 5), ('bob', 3), ('ann', 7);
SELECT * FROM totals ORDER BY user;
```

```text
+------+-------+
| user | total |
+------+-------+
| ann  | 12    |
| bob  | 3     |
+------+-------+
```

Write another row and the view has it already:

```sql
INSERT INTO events VALUES ('bob', 4);
SELECT * FROM totals ORDER BY user;
```

```text
+------+-------+
| user | total |
+------+-------+
| ann  | 12    |
| bob  | 7     |
+------+-------+
```

The folder `lake` now holds your tables. Stop Pondra, copy the folder to a bucket, and it opens there as
it was.
[How Pondra works](/pondra/concepts/how-it-works/) explains what is in it, and
[Your first lake](/pondra/start/first-lake/) does the same from Python and JavaScript.
