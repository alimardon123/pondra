Pondra is one program that takes in streams of rows, keeps them as tables in a folder or a bucket
(Parquet files and a small catalog), and answers SQL. Views stay current as rows arrive, other
engines read the tables as Delta Lake or Iceberg, and the same binary on a second machine joins the
first as a cluster. There is no Kafka, Flink, Spark, JVM or metastore to run.

## One binary replaces

For the common jobs, `pondra` takes the place of a stack:

| Instead of running | For | Pondra has |
|---|---|---|
| **Kafka** | Ingesting events, topics, consumers | Exactly-once appends, and a Kafka port: producers, consumers and Debezium change events |
| **Flink** | Streaming SQL: windows, joins, deduplication | Materialized views over any query, event-time windows, stream joins, `ASOF JOIN`, tasks |
| **Spark** | Batch SQL, ELT and DataFrames | SQL spread over the nodes, frames with Polars' names, and PySpark's names in `pondra.spark` |
| **A metastore** (Hive, Polaris, Unity) | The catalog of tables | A catalog inside the bucket, and an Iceberg REST catalog on every node |
| **ZooKeeper** | Picking a leader | A leader elected through the bucket |

Pondra is new: it has a large test suite (crashes, failovers and clients, on local disk and on object
storage) and published benchmarks, but it hasn't run for years in production as they have.
[Pondra compared](/pondra/concepts/compared/) says where each of them is stronger.

## Try it in 30 seconds

Install Pondra with pip ([other ways](/pondra/start/install/)) and start the shell on a folder called
`lake`:

```bash norun
pip install pondra
pondra
```

Then type SQL. This makes a table and a view that keeps its totals current, writes three rows, and
reads the totals:

```sql
CREATE TABLE events (user VARCHAR, amount BIGINT);
CREATE MATERIALIZED VIEW totals AS SELECT user, sum(amount) AS total FROM events GROUP BY user;
INSERT INTO events VALUES ('ann', 5), ('bob', 3), ('ann', 7);
SELECT * FROM totals ORDER BY user;
```

```text
+------+-------+
| user | total |
+------+-------+
| ann  | 12    |
| bob  | 3     |
+------+-------+
```

Write another row and the view has it already:

```sql
INSERT INTO events VALUES ('bob', 4);
SELECT * FROM totals ORDER BY user;
```

```text
+------+-------+
| user | total |
+------+-------+
| ann  | 12    |
| bob  | 7     |
+------+-------+
```

The folder `lake` now holds your tables: copy it to a bucket and it opens there as it was.
[Your first lake](/pondra/start/first-lake/) does the same from Python and JavaScript.
