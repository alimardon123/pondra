Every node answers HTTP on its `--addr` (default `127.0.0.1:8080`). The Python and JavaScript
clients, the shell and the console all use these endpoints, and so can `curl`. Any node takes any
request. A request that changes a table, view, task or function goes to the leader, and a
follower forwards it there.

With a certificate (`--tls-cert` and `--tls-key`), the node takes `https://` on the same port. A
plain `http://` request from another machine is refused with `403` and the reason. Plain requests
are taken from this machine only, unless `PONDRA_TLS=optional`. See [TLS](/pondra/guides/security/#tls).

## Roles

A node started without tokens is open. With `--read-token`, `--write-token` and `--admin-token`
(or the `PONDRA_*_TOKEN` variables), a request carries `Authorization: Bearer <token>`, and the
token's role decides what it may do. A role covers the ones before it: admin, then write, then
read. A user who signs in with `POST /login` gets a token of their own, sent the same way. The
[security guide](/pondra/guides/security/) has the users and their grants.

| Role | May |
|---|---|
| none | the console's page and files, `GET /stats`, `GET /healthz`, `GET /ready`, `POST /login`, `GET /whoami`, `/console/settings`, and a procedure's `GET /secrets/{name}` (its lent token only) |
| read | run queries (`POST /sql`, `GET /sql/pages/{id}`), look up keys, watch, live queries, read files, end a session, `GET /objects`, `GET /kinds`, `GET /routines`, `GET /metrics`, the projects' `plan`, `test`, `status` and `export`, the Iceberg catalog's reads, MCP's reads, the Delta Sharing door |
| write | also append rows, insert, put, restore and delete files, write with `POST /sql`, and commit to the Iceberg catalog |
| admin | also create tables, views, tasks and functions, `POST /tier`, Python (`/python`, `/sessions/{id}/python`), `GET /functions`, making and dropping databases in a folder of lakes, DDL in `POST /sql` (`CREATE`, `ALTER`, `DROP`, `COPY … TO`), `DO` blocks, and `apply` |

`apply` needs an admin token, or the `APPLY` privilege on the database. Other rights a route checks
inside its handler, such as a write statement's, are listed where the route is.

```bash norun
curl -s -H "Authorization: Bearer $PONDRA_TOKEN" -X POST http://localhost:8080/sql -d "SELECT 1"
```

## Status codes

Every answer has one of these codes. Errors that a route doesn't name below are `500`, with the
message as the body.

| Status | When | Body |
|---|---|---|
| `200` | the answer | the JSON or text the route describes |
| `204` | a change with no answer: `PUT /console/settings`, an Iceberg table's commit or drop, a rename | empty |
| `304` | a console file that hasn't changed, when `If-None-Match` names its `ETag` | empty |
| `400` | a request the route can't use: a folder of lakes' bad name, an Iceberg `POST /v1/namespaces` (use `CREATE SCHEMA`), a Delta Sharing feature not yet offered | text, or an Iceberg or Delta Sharing error object |
| `401` | no token, a wrong token, or a wrong user name or password. A `POST /login` with a wrong password is `401` too | `sign in: a token, or a user's name and password`, `wrong token, or user name and password`, `wrong user name or password` |
| `403` | the token or user has too few rights for the route. Also a plain request from another machine when the node takes TLS | `this needs more rights than this token's or user's`, or the TLS message |
| `404` | no such file, version, namespace or table; an unknown path; a folder's database that can't be started | the name, and the reason |
| `409` | `PUT /files/{path}` with no `If-Match` to a path that exists; an Iceberg commit against a table that changed meanwhile (`CommitFailedException`) | the reason |
| `410` | `GET /sql/pages/{id}` for an answer no longer kept | `this answer's rows are no longer kept here: run it again` |
| `412` | `PUT /files/{path}` with an `If-Match` the file has moved past | the path and the change |
| `422` | a JSON body that lacks a field the route needs, such as `POST /plan` without `files` | the field, as the JSON reader names it |
| `500` | any other error, such as a bad statement or a refused statement | the message as text, and the `x-pondra-sqlstate` header |
| `502` | a folder of lakes can't reach a running database's node | the reason |
| `503` | the node is stopping, or it leads but can't reach its bucket; `/ready` while it catches up | the reason; `Retry-After: 1` when the node is stopping or cut off |

A `500` carries a header with Postgres's code for the error, `x-pondra-sqlstate`, so a client can
tell a syntax error from a conflict without reading the words. Only the `500` answers have it. The
codes are listed in [error codes](/pondra/reference/postgres/#error-codes).

```bash
curl -s -i -X POST http://localhost:8080/sql -d "SELEC 1" | grep -i "^HTTP\|x-pondra-sqlstate"
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/files/no/such.txt
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/sql/pages/none
```

```text
HTTP/1.1 500 Internal Server Error
x-pondra-sqlstate: 42601
404
410
```

A node that is stopping answers every other path with `503` and `Retry-After: 1`: send the request
to another node. A node that leads but can't reach its bucket answers `503` the same way, while
another node takes over. A node that has just started answers queries `500` with
`x-pondra-sqlstate: 57P03` until it has what its leader had. `GET /ready` says which of these holds
(below).

## Run SQL

| Method and path | Role | Meaning |
|---|---|---|
| `POST /sql` | read (write and admin for statements that change things) | run one or more statements; answer with the last one's rows or outcome |
| `GET /sql/pages/{id}?from=&rows=` | read | more rows of an answer of more than 10,000 (`format=typed`'s `pages`), kept on the node a while: `410` once it isn't |

The body is SQL text. To send parameters, send JSON with `Content-Type: application/json`:
`{"sql": "…", "params": {"min": 5}}`. Parameters are `$name` in the SQL; a value is JSON, or
`{"sql": "DATE '2026-09-27'"}` for one that JSON has no type for. `views` (a map of a name to a
query) and `tables` are for clients that send frames and data along; the clients build them.

| Query parameter | Meaning |
|---|---|
| `format` | `json` (the default), `table` (a text table), `arrow` (an Arrow IPC stream, for pandas, Polars and DuckDB) or `typed` (below); or a file of every row to download: `csv`, `tsv`, `ndjson` (JSON lines), `parquet` or `xlsx` (an Excel workbook: one sheet, the names in bold, at most 1,048,575 rows) |
| `after` | wait until this node has seen this log segment (from an append's `seg`), for reading your own writes |
| `spread` | `1` runs the query across the cluster even for small tables, `0` only here. Left out, the cluster decides ([clusters](/pondra/guides/clusters/)) |
| `stale_ms` | accept a remembered answer up to this many milliseconds old |
| `job` | for a write: a retry with the same job id is applied once |
| `rows` | `typed` only: how many rows the first page holds (1 to 100,000; 10,000 if left out) |

A query answers a JSON array of rows, one object each. A column that is null in a row is left out
of its object. A statement that isn't a query answers a JSON object, such as `{"rows": 2}` or
`{"table": "t", "publish": []}`. Several statements in one request run in order.

`format=typed` is what [the console](/pondra/start/console/) uses: `{"columns": [{"name", "type"}],
"rows": [[…], …], "total": N, "pages": "…"}`. Each row is a list in the columns' order, so two
columns may share a name (a join's). It holds the first 10,000 rows (`&rows=N` for another number,
1 to 100,000: the console's rows a page), and `total` says how many there were. Decimals come as text
with all their digits (`"1.50"`), and so do integers past 2^53, which JavaScript can't hold exactly.

An answer of more rows than that is kept on the node a while, and `pages` is its id (else `null`).
`GET /sql/pages/{id}?from=10000&rows=10000` answers more of its rows, in the same form: the same rows
in the same order, without running the query again. The node keeps such answers within
`PONDRA_PAGES_MB` (256) in all, for 20 minutes after each was last read; one no longer kept answers
`410`, and the query can be run again (`LIMIT … OFFSET …`). The id is random: only whoever was sent
the answer knows it, and reading a page needs the read token, as `/sql` does.

```python
import json, urllib.request

def post(sql):
    return json.load(urllib.request.urlopen(urllib.request.Request("http://localhost:8080/sql?format=typed", sql.encode(), method="POST")))

first = post("SELECT value AS n FROM range(0, 25000)")
more = json.load(urllib.request.urlopen(f"http://localhost:8080/sql/pages/{first['pages']}?from=20000&rows=10000"))
print(first["total"], len(first["rows"]), len(more["rows"]), more["rows"][0])
```

```text
25000 10000 5000 [20000]
```

The header `x-pondra-notices` on an answer carries what procedures and `DO` blocks printed, as a
JSON list of lines. Send `x-pondra-session: <id>` (8 to 128 letters, digits, `-` or `_`) to use
temporary tables that only that id sees, `DO LANGUAGE python` blocks that share their variables
([Functions and procedures](/pondra/guides/functions-and-procedures/#cells-that-share-variables)),
and a transaction: `BEGIN`, then statements, then `COMMIT`, each request with the same id
([Transactions](/pondra/guides/change-rows/#transactions)). A node answers `x-pondra-session: held`
while it keeps that session's state, and a client keeps to that node meanwhile.

```bash
curl -s -X POST http://localhost:8080/sql -d "CREATE TABLE events (user VARCHAR, amount BIGINT)"
curl -s -X POST http://localhost:8080/sql -d "INSERT INTO events VALUES ('ann', 5), ('bo', 7)"
curl -s -X POST http://localhost:8080/sql -d "SELECT user, sum(amount) AS total FROM events GROUP BY user ORDER BY user"
curl -s -X POST http://localhost:8080/sql -H 'content-type: application/json' -d '{"sql": "SELECT * FROM events WHERE amount > $min", "params": {"min": 5}}'
curl -s -X POST 'http://localhost:8080/sql?format=table' -d "SELECT * FROM events ORDER BY user"
```

```text
{"table":"events","publish":[]}
{"rows":2}
[{"user":"ann","total":5},{"user":"bo","total":7}]
[{"user":"bo","amount":7}]
+------+--------+
| user | amount |
+------+--------+
| ann  | 5      |
| bo   | 7      |
+------+--------+
```

## Write rows

| Method and path | Role | Meaning |
|---|---|---|
| `POST /append/{table}` | write | append rows exactly once |
| `POST /insert/{table}` | write | run a query and write its rows as files, in bulk |

`POST /append/{table}?producer=NAME&seq=N[&prev=M]`: the body is newline-delimited JSON, one row
per line, or an Arrow IPC stream with `Content-Type: application/vnd.apache.arrow.stream`. A
column left out takes its `DEFAULT`, or null. `producer` names the writer and `seq` counts its
appends, from 1 (`seq=0` is refused), so a retry with the same `producer` and `seq` is recognised
and not applied twice. `prev` is a compare-and-swap: the append applies only if the producer's last
`seq` is `prev`. Without `producer`, an append is applied each time it is sent (at least once), as a
Kafka producer that isn't idempotent. The answer is:

| Field | Meaning |
|---|---|
| `seg` | the log segment that holds the rows |
| `duplicate` | true if this `seq` was already applied, so nothing was written |
| `conflict` | true if `prev` didn't match: read again and retry |
| `refused` | true if a table with a `UNIQUE` constraint refused the rows: a duplicate value |
| `gone` | true if the table was renamed or dropped as the rows came: nothing was written |
| `row` | where the rows start among the table's rows in `seg` |
| `ms` | the commit time, for a reservation |
| `block` | the block of row ids a reservation took, `0` for an append that took none |

`POST /insert/{table}?job=ID`: the body is a query, such as `SELECT * FROM events`. The node runs
it and writes the rows as Parquet, and the table is made if it doesn't exist. The answer is
`{"rows": N}`, or `{"duplicate": true}` if this `job` was already applied.

```bash
curl -s -X POST 'http://localhost:8080/append/events?producer=p1&seq=1' -H 'content-type: application/x-ndjson' --data-binary $'{"user":"cy","amount":3}\n{"user":"di","amount":4}\n'
curl -s -X POST 'http://localhost:8080/append/events?producer=p1&seq=1' --data-binary $'{"user":"cy","amount":3}\n'
curl -s -X POST 'http://localhost:8080/insert/events_copy?job=copy-1' -d "SELECT * FROM events"
curl -s -X POST 'http://localhost:8080/insert/events_copy?job=copy-1' -d "SELECT * FROM events"
```

```text
{"seg":3,"duplicate":false,"conflict":false,"row":0,"ms":0,"block":0}
{"seg":0,"duplicate":true,"conflict":false,"row":0,"ms":0,"block":0}
{"rows":4}
{"duplicate":true}
```

## Tables, views and tasks

| Method and path | Role | Meaning |
|---|---|---|
| `POST /tables/{name}` | admin | make a table from a JSON definition, or change an existing one (add columns at the end, `publish`, `cluster_by`, `ttl`, `order_by`) |
| `POST /views/{name}` | admin | make a materialized view; the body is its query, and its options are query parameters |
| `POST /tasks/{name}` | admin | make a task that runs a query over a source table into a target, as it arrives |

The body of `POST /tables/{name}` is either a list of `[name, type]` pairs, with Arrow's type names
(`Utf8`, `Int64`, `Float64`, `Boolean`, `Timestamp(Microsecond, None)`), or an object with
`columns` and the options: `key` (a list), `merge` (an object of column to function), `publish`
and `cluster_by` (lists), `partition_by`, `ttl` and `order_by` (strings). See
[table options](/pondra/sql/table-options/#the-same-options-over-http). The answer is
`{"table": name, "publish": […]}`.

`POST /views/{name}?window=w&size_secs=60&lateness_secs=10` takes any of the options of
[`CREATE MATERIALIZED VIEW`](/pondra/sql/table-options/#materialized-views) as query
parameters. The answer is `{"view": name, "materialized": true}`.

`POST /tasks/{name}` takes JSON: `source` and `target` (table names), `sql` (the query over the
source), `key` (the target's primary key, to make it an upsert table), `shards` (default 1) and
`shard_by` (a column, needed when `shards` is more than 1). The answer is `{"task": name}`.

```bash
curl -s -X POST http://localhost:8080/tables/points -d '{"columns": [["id", "Int64"], ["label", "Utf8"]], "key": ["id"]}'
curl -s -X POST http://localhost:8080/tables/ticks -d '[["ts", "Timestamp(Microsecond, None)"], ["amount", "Float64"]]'
curl -s -X POST 'http://localhost:8080/views/spend?window=w&size_secs=3600' -d "SELECT date_bin(INTERVAL '1 hour', ts) AS w, sum(amount) AS total FROM ticks GROUP BY 1"
curl -s -X POST http://localhost:8080/tasks/per_user -d '{"source": "events", "target": "per_user", "sql": "SELECT user, sum(amount) AS total FROM events GROUP BY user", "key": ["user"]}'
```

```text
{"table":"points","publish":[]}
{"table":"ticks","publish":[]}
{"view":"spend","materialized":true}
{"task":"per_user"}
```

## Read and follow

| Method and path | Role | Meaning |
|---|---|---|
| `GET /lookup/{table}/{key}` | read | the current row of one key of a keyed table |
| `GET /watch/{table}` | read | a stream of a table's new rows as they commit |
| `GET /live?sql=…` or `POST /live` | read | a stream of a query's answer, again each time a commit changes it |

`GET /lookup/{table}/{key}` answers a JSON array with the row, or `[]`. A composite key is the
values, comma-separated, in the key's column order. It is an error for a table with no key.

`GET /watch/{table}` streams newline-delimited JSON, one row per line, for as long as you keep the
connection open. Its parameters: `after=N` (replay from this position; the default is from now on,
and a replay goes as far back as the log is kept), `marks=true` (after each batch of rows, a line
`{"_after": N}`: resume with `?after=N`) and `changes=true` (the change feed: UPDATE's and DELETE's
rows too, each with `_change_type`, `_row_id`, `_version`, `_created_at` and `_updated_at`). A user
whose grants don't cover the whole table's rows gets `403`.

`/live` answers a query now, and again each time a commit changes a table it reads, as lines of
`{"at": COMMIT, "rows": […]}`. `GET /live?sql=…` takes the query in the URL, and `POST /live`
takes a body as `POST /sql` does, with `$name` parameters. `every_ms` sets the shortest time between
queries on a busy table (default 100). An answer that comes out the same isn't sent again. A line
`{"error": …}` ends the stream. The query runs while the connection is open, and stops when it
closes.

Several live queries share one connection with `POST /live` and a JSON body `{"queries": [{"id":
"a", "sql": "…", "params": {…}, "session": "…"}, …]}`: each line names its query's `id`, a query
that can't be watched sends its own `{"id": …, "error": …}` line while the others go on, and
`session` is the `x-pondra-session` that query runs in. A browser opens six connections to a host at
most, so a page that shows several live answers (the console's) needs this.

```bash
curl -s http://localhost:8080/lookup/points/1
curl -s --max-time 2 'http://localhost:8080/watch/events?after=0&marks=true' || true
curl -s --max-time 2 -G http://localhost:8080/live --data-urlencode 'sql=SELECT count(*) AS n FROM events' || true
curl -s --max-time 2 http://localhost:8080/live -H 'content-type: application/json' \
  -d '{"queries": [{"id": "n", "sql": "SELECT count(*) AS n FROM events"}, {"id": "one", "sql": "SELECT 1 AS one"}]}' || true
```

```text
[]
{"user":"ann","amount":5}
{"user":"bo","amount":7}
{"user":"cy","amount":3}
{"user":"di","amount":4}
{"_after":7}
{"at":8,"rows":[{"n":4}]}
{"id":"one","at":8,"rows":[{"one":1}]}
{"id":"n","at":8,"rows":[{"n":4}]}
```

On a shared connection, each line names its query by `id`, and lines of different queries can come
in any order.

## Files

The lake's own files, under `files/`: notebooks, SQL and Python files, data files, images. The
console's Workspace shows them and edits them in place.

| Method and path | Role | Meaning |
|---|---|---|
| `PUT /files/{path}` | write | store the body at `files/{path}`; a new file, or with `If-Match` the file replaced |
| `GET /files/{path}` | read | the file's bytes, its version as `etag`, and a content type by its name |
| `DELETE /files/{path}` | write | remove it (its versions stay) |
| `GET /files/{path}?versions` | read | its versions, newest first: `[{"id", "at", "who", "bytes"}]` |
| `GET /files/{path}?version={id}` | read | one version's bytes |
| `POST /files/{path}?restore={id}` | write | that version made the file again (and kept as the newest) |

- **A new file:** a `PUT` with no `If-Match` to a path that exists is refused with `409`, so a
  file is never overwritten blind.
- **Replacing one:** send the `etag` a `GET` gave as `If-Match`. If someone saved the file since,
  the `PUT` is refused with `412`, and theirs is kept: read it again, or save under another name.
- **The answer to `PUT`** is `{"path": "files/{path}", "bytes": N, "version": "…"}`, the version
  the next `If-Match` needs. A `GET` of a path with no file is `404`.
- **The answer to `DELETE`** is `{"removed": "files/{path}"}`. `POST ?restore=` answers
  `{"path", "version", "restored"}`, with the version it made the file again.
- **Every node reads a replaced file's new bytes** at its next statement: nothing caches `files/`
  (not the SSD tier either). The rest of the lake is never overwritten, so it is cached.
- **Every save is kept as a version**, with who made it and when, in `files/.versions/` (which
  `files()` doesn't list): the newest 50 for 90 days (`PONDRA_FILE_VERSIONS`,
  `PONDRA_FILE_VERSIONS_DAYS`), files up to 64 MB. A deleted file keeps its versions, so it can be
  restored. The console's **Versions…** shows what changed and restores one.

Read them from SQL with `files()` and `file_read()`, see [functions](/pondra/sql/functions/#files).

```bash
curl -s -X PUT http://localhost:8080/files/notes/a.txt --data-binary 'hello'
curl -s http://localhost:8080/files/notes/a.txt; echo
v=$(curl -sI http://localhost:8080/files/notes/a.txt | tr -d '\r' | sed -n 's/^etag: //ip')
curl -s -X PUT http://localhost:8080/files/notes/a.txt -H "If-Match: $v" --data-binary 'hello again'
curl -s -X PUT http://localhost:8080/files/notes/a.txt -H "If-Match: $v" --data-binary 'too late'; echo
curl -s -X DELETE http://localhost:8080/files/notes/a.txt
first=$(curl -s "http://localhost:8080/files/notes/a.txt?versions" | python3 -c "import json, sys; print(json.load(sys.stdin)[-1]['id'])")
curl -s -X POST "http://localhost:8080/files/notes/a.txt?restore=$first" > /dev/null
curl -s http://localhost:8080/files/notes/a.txt; echo
```

```text
{"path":"files/notes/a.txt","bytes":5,"version":"…"}
hello
{"path":"files/notes/a.txt","bytes":11,"version":"…"}
files/notes/a.txt: the file changed since it was opened: open it again, or save under another name
{"removed":"files/notes/a.txt"}
hello
```

A `PUT` with no `If-Match` to a path that exists answers `409`, and a `GET` of its `?version=`
that isn't one of the file's answers `404`. Both are plain text. A `304` isn't sent for files: a
`GET` always answers the bytes.

## Functions, routines and secrets

| Method and path | Role | Meaning |
|---|---|---|
| `POST /functions/{name}` | admin | register a function run by your own Arrow Flight server |
| `DELETE /functions/{name}` | admin | remove it |
| `GET /functions` | admin | the lake's registered Flight functions, as an object by name |
| `GET /routines` | read | the lake's SQL and Python functions and procedures, as an object by name |
| `GET /secrets/{name}` | none | a secret's values: only for the token a running Python procedure is lent |

The body of `POST /functions/{name}` is `{"flight": "http://host:port", "args": ["Utf8"], "returns":
"Utf8", "rows": N}`, where `rows` is optional. A body that doesn't read answers `500` with the shape it
expects. See [functions](/pondra/sql/functions/#functions-you-bring). The answer is `{"function": name}`,
and `{"dropped": name}` for `DELETE`.

`GET /secrets/{name}` is what `pondra.secret(name)` calls inside a Python procedure. Any other
token is refused, and so is a request with no token.

## Projects

A project's files go to the node that holds the database, with the environment's values and the
git commit: the command line sends them, and [apply a project](/pondra/guides/environments/#apply-a-project)
says what each request does. Every project route takes the same body:

| Field | Meaning |
|---|---|
| `files` (required) | the project's files: a map of path to text, `pondra.toml` and `objects/`, `migrations/`, `seeds/`, `tests/` |
| `env` | the environment whose `[env.…]` values and attached catalogs apply |
| `commit` | the git commit, when the project is in git |
| `secrets` | `$name` values from the applying machine: bound for the run, never kept |
| `test` | `apply` only: run the tests after it |
| `prune` | drop what the project no longer declares |
| `plan` | `apply` only: the plan's `id` it showed; refused if the plan has changed since |
| `names` | `capture` only: the objects to write (none: all of them) |

| Method and path | Role | Meaning |
|---|---|---|
| `POST /plan` | read | what an apply would change, and what it refuses: `{"plan": {"id", "after", "steps", "refused", "tests"}, "project", "ok"}` |
| `POST /apply` | admin, or APPLY on the database | apply the plan, then the tests: `{"apply", "status", "steps", "tests", "ok"}` |
| `POST /test` | read | the project's tests alone: `{"tests": [...], "ok"}` |
| `POST /status` | read | what differs from the database: to apply, changed outside an apply, untracked (`pondra status`): `{"status": {"after", "lines", "refused"}, "project", "ok"}` |
| `POST /capture` | admin, or APPLY on the database | the files that write the chosen changed and untracked objects into the project, with a migration for a rename: `{"files", "captured", "migrations", "refused", "ok"}`, where each file's value is its new text (`null`: removed). The command line writes them (`pondra capture`) |

```bash
curl -s -X POST http://localhost:8080/plan -H 'content-type: application/json' \
  -d '{"files": {"pondra.toml": "[project]\nname = \"demo\"\n"}}'
```

```text
{"plan":{"id":"d20f079062a3c20e","after":0,"steps":[],"refused":[],"tests":0,"new":true},"project":"demo","ok":true}
```

A project route with no `files` answers `422`. A project whose `pondra.toml` is missing or names no
project answers `500`, with the reason.

## The server

| Method and path | Role | Meaning |
|---|---|---|
| `GET /stats` | none | health and position, as JSON |
| `GET /healthz` | none | `ok` (200) while the process runs: a liveness check |
| `GET /ready` | none | `ready` (200) when the node serves; `503` with the reason while it stops (`stopping`), while it catches up with its leader after a start (`catching up with the leader`), or when it can't reach its bucket (`can't reach the bucket: another node leads`): a readiness check |
| `POST /login` | none | `{"user", "password"}`: a session for the user, answered `{"token": "ps_…", "until": ms, "user": name}`, to send as `Authorization: Bearer …` until it ends (`PONDRA_SESSION_HOURS`); `401` for a wrong password |
| `GET /whoami` | none | who the request signs in as: `{"user", "role", "superuser", "open"}`; `role` is `admin`, `write`, `read` or `none` |
| `GET /objects` | read | the lake's objects, and the lakes attached to it, as `{"objects": [...], "files": ...}`. Each object has `catalog`, `schema`, `name` and `kind` (`table`, `view`, `materialized view`, or `files` for [a view of files](/pondra/sql/statements/)); a table adds its `rows`, `bytes`, `files`, `key`, `partition`, `cluster`, `publish`, `not_null` and `defaults`, a view its `sql`. `files` says where the lake's own files are, for `read_csv('…')`. What the console's catalog shows |
| `GET /kinds` | read | every kind of object, part and pattern, one row each, as [`pondra.kinds`](/pondra/sql/system-tables/#every-object) lists them: `[{"kind", "is", "family", "inside", "statements", "privileges", "on_clone", "in_project", "undrop", "secret", "lists", "about", "also"}]`; a column that doesn't apply is `null`. The [glossary](/pondra/sql/glossary/) says what each one is |
| `GET /export` | read | the project files that describe this database: a map of path to text, `pondra.toml` and an `objects/` file for each object. `?database=NAME` exports an attached database as this node sees it (`pondra diff` reads it that way) |
| `GET /metrics` | read | Prometheus metrics, as text |
| `POST /tier` | admin | write the log into Parquet now: `{"rows_tiered": N}` |
| `DELETE /sessions/{id}` | read | end a session: its temporary tables and views go, and so does its Python: `{"ended": true}` (`false` if it had none) |
| `GET /sessions/{id}/python` | admin | the session's Python (a console page's cells): `{"running", "busy", "variables": [{"name", "type", "size", "look"}], "python": {"python", "version"}}` |
| `POST /sessions/{id}/python` | admin | interrupt its running cell: it ends with `KeyboardInterrupt` and the variables stay (`{"done": "interrupted"}`); on Windows Python restarts instead (`"restarted"`) |
| `DELETE /sessions/{id}/python` | admin | restart it: its variables go, its temporary tables stay (`{"restarted": true}`) |
| `GET /python` | admin | the Python workers run with: `{"python", "version"}`; with `?all=1`, also `pythons`: each Python this machine has, tried (`path`, `version`, `pondra`, `pyarrow`, `ok`, `error`) |
| `PUT /python` | admin, from this machine | `{"path": "…"}`: run workers with that Python from now on (it must have `pondra` and `pyarrow`), and next time too. Workers running now finish with the Python they have. Refused from another machine |
| `POST /python/format` | admin | `{"code": "…"}`: Python code formatted by the node's Python, as ruff (or black, if it has no ruff) formats it: `{"code": "…"}`. The code is only read, never run |
| `GET /` | none | [the console](/pondra/start/console/): a web page, with no data in it until you use it |
| `GET /console/{file}` | none | the console's scripts, style sheet and modules by name (`console.js`, `console.css`, and the modules it loads, some the first time they are needed), and the extensions the node was given (`ext/{n}.js`, from `PONDRA_CONSOLE_EXTENSIONS`). Each has an `ETag`, and `304` when `If-None-Match` names it. `404` for a name it doesn't have |
| `GET /console/settings` | none | the console's settings kept on this machine (theme, colours, layout), as JSON: `{}` if none |
| `PUT /console/settings` | none, from this machine | keep them: a JSON object, at most 64 KB; `204`. From another machine `403`, and that page keeps its own. A body that isn't one JSON object is `400` |

`GET /stats` needs no token, so a load balancer can poll it. It answers `lake` (its name), `role` (`leader`,
`follower` or `reader`), `leader` (its address), `term`, `nodes`, `hwm` (the newest commit),
`shard_runs`, `python_workers`, `live_queries`, `version` (the node's release), `format` (the
lake's, see [upgrades](/pondra/guides/upgrades/#which-releases-can-open-a-lake)) and `keys` (how the
lake's own keys are kept: `sealed` by the master key, `clear`, or `none` until the lake makes them). On the leader it also has
`untiered_rows`, `commits`, `commit_ms_p50`, `commit_ms_p95` and `releases` (each live node's
release, by address).

```bash
curl -s http://localhost:8080/stats
curl -s http://localhost:8080/metrics | head -3
curl -s -X POST http://localhost:8080/tier
```

# HELP pondra_role 1 for this node's role

## A folder of lakes

[`pondra serve`](/pondra/guides/server/) on a folder of lakes answers on one port for every database in it:

| Method and path | Role | Meaning |
|---|---|---|
| `/db/{name}`, `/db/{name}/{*rest}` | as on a node | database `name`'s whole API, the node's path after its name: `POST /db/sales/sql`, `GET /db/sales/stats`, … |
| any other path | as on a node | the default database's (`--default`) |
| `GET /databases` | read | the databases: `[{"name", "running", "default"}]` |
| `POST /databases` | admin | make one: `{"name": "hr"}`, as `CREATE DATABASE hr`; `400` with the reason if it can't |
| `DELETE /databases/{name}` | admin | drop one, folder and all, as `DROP DATABASE`; `?if_exists=true` is quiet about one that isn't there. `400` with the reason if it can't |
| `GET /console/…` | none | the console's files and settings, as on a node. `GET /` lists every database |

A database's node starts when its first request comes. If it can't start, the request answers `404`
with the reason, and if a running node stops answering, `502`.

```bash norun
curl -s http://localhost:8080/db/sales/stats
curl -s -X POST http://localhost:8080/db/sales/sql -d "SELECT count(*) FROM orders"
```

## Delta Sharing

A node shares tables with other companies over the Delta Sharing protocol, at `/delta-sharing/…`.
A recipient signs in with the token its profile gives it, as `Authorization: Bearer`, and reads only
what the share names. [Sharing](/pondra/guides/sharing/) has the whole of it: making shares and
recipients, the profile and the client.

| Method and path | Meaning |
|---|---|
| `GET /delta-sharing/shares` | the shares this recipient may read |
| `GET /delta-sharing/shares/{share}` | one share |
| `GET /delta-sharing/shares/{share}/schemas` | its schemas |
| `GET /delta-sharing/shares/{share}/schemas/{schema}/tables` | the tables of a schema in the share |
| `GET /delta-sharing/shares/{share}/all-tables` | every table of the share |
| `GET`, `HEAD …/tables/{table}/version` | the table's current version; `?startingTimestamp=` for the version at that time |
| `GET …/tables/{table}/metadata` | the table's protocol and metadata |
| `POST …/tables/{table}/query` | the table's files for a query: a body with `version` or `timestamp` reads that version |
| `GET …/tables/{table}/changes` | refused for now: `400 FEATURE_NOT_SUPPORTED` |
| `GET`, `HEAD /delta-sharing/files/{link}` | one file, through a link that ends. A `Range` request answers `206` |

A missing or unknown token is `401` with `errorCode` `UNAUTHENTICATED`. A link that isn't valid, or
has ended, is `403` with `PERMISSION_DENIED`. More files a minute than `PONDRA_SHARE_FILES_PER_MINUTE`
(10000) is `429`. Every request at this door is a row of `pondra.audit`, refusals too.

## Other doors on the same port

| Path | Role | What it is |
|---|---|---|
| `POST /mcp` | read (writes need more) | the MCP server: see [MCP](/pondra/reference/mcp/) |
| `/v1/…` | read; write for `POST` and `DELETE` | the Iceberg REST catalog: see [Iceberg REST](/pondra/reference/iceberg-rest/) |
| `/delta-sharing/…` | a recipient's token | Delta Sharing: see the table above |

The Postgres port, Arrow Flight and Kafka listen on their own ports: [Postgres](/pondra/reference/postgres/),
[Flight](/pondra/reference/flight/) and [Kafka](/pondra/reference/kafka-protocol/).

## Between nodes

Nodes in a cluster call each other on `/cluster/…` paths, over HTTPS when the node has a certificate.
You don't call them, and a firewall between nodes must let HTTP through. Each call carries the
caller's release and lake format (`x-pondra-version` and `x-pondra-format`), so the leader knows when
every node can read a newer format.

<Aside type="caution">
A request body is limited to 1 GiB. The body of an append or an insert must fit in memory on
the node that takes it, so send big loads in batches.
</Aside>
