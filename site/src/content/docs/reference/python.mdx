The `pondra` package talks to a node over HTTP. `pondra.connect` is the one way in: it reaches a node
that is running, or opens a lake and runs its node inside this process. Either way it returns a
connection, a `pondra.Pondra`, called `db` on this page. It runs SQL, writes rows, makes views, and calls
functions and procedures. A query comes back as a **frame**, which the
[frames reference](/pondra/reference/frames/) covers.

```python
import pondra
db = pondra.connect("http://localhost:8080")
```

## Connect

| Call | Meaning |
|---|---|
| `pondra.connect(target=None, token=None, **options)` | the one way in: a connection to the lake or node `target` names, with its node in this process when it is a lake (below) |
| `pondra.current()` | the connection `pondra.sql` and its kin use |
| `pondra.binary()` | the path of the `pondra` executable: `$PONDRA_BIN`, the one pip installed, or the one on `PATH` |

`target` says what to connect to:

- **Nothing, or `":memory:"`** (as DuckDB spells it): a new lake held in this process's memory, gone at `close()`.
  Past `PONDRA_MEMORY_LAKE_GB` (a quarter of the machine's memory) its files go to a folder of its own on disk, removed at `close()` too. `db.save('lake')` (or a bucket's URL) keeps it: the lake moves there and the connection goes on over it (`ALTER DATABASE … SET LOCATION`).
- **A folder, or a bucket's URL** (`s3://`, `gs://`, `az://`): that lake. Its node runs inside this process,
  through the library the package ships, so there is no second process to start. Its SQL may read and write
  files on this machine (`read_csv('jan.csv')`), and its Python procedures run with this Python (`python=False`
  gives it none). It listens on 127.0.0.1 at `port=` (a free port if none), for the console and other
  programs. The other options are the node's [settings](/pondra/reference/environment/) by name:
  `memory_gb=2` is `PONDRA_MEMORY_GB`. They are fixed by the first node a process opens; a misspelt one is
  refused, naming the nearest.
- **`http://` or `https://`** (or a list of them, any of a cluster's nodes): a node running somewhere, with the
  options below.

A process holds one such node at a time. The same lake connected again is another connection to that node.
Another lake connected while one is open gets a node of its own beside the process. A node stops with the
last connection to it, or when Python exits; a folder's or a bucket's lake stays.

`pondra.local()` and `pondra.open()` still work, with a warning, until 1.0.

A connection to a node takes these options:

| Option | Default | Meaning |
|---|---|---|
| `token` | none | sent as `Authorization: Bearer …`; the token's role decides what the connection may do |
| `producer` | random | the name `append` writes under, for exactly-once |
| `timeout` | 300 | seconds to wait for an answer |
| `headers` | none | extra headers for every request |
| `job` | none | a job id: the connection's writes are numbered under it, so a retry is applied once |
| `echo` | `True` | print what procedures print (their notices) as well as keep them in `db.notices` |
| `retry_secs` | 60 | how long a call keeps trying while no node answers it (0: once) |

Given a cluster's nodes, a connection rides out one going away. A call that no node ran (nobody
there, a node stopping, a leader cut off from its bucket) goes to the next node, and so does one a
node may have run if sending it again can't apply it twice: a query, an `append`, and a single
`INSERT`, `UPDATE`, `DELETE` or `MERGE`, which the connection sends with a job. It keeps trying for
`retry_secs`; a single address that has never answered is said at once.

```python norun
db = pondra.connect(["http://10.0.0.1:8080", "http://10.0.0.2:8080", "http://10.0.0.3:8080"])
```

While a node holds the connection's session (a transaction, temporary tables, `SET`, variables, the
session's Python), every call goes to that node. If it goes away, the next call fails with SQLSTATE
`08006`, the session's state is gone, and the call after that starts again on another node.

```python norun
db = pondra.connect("https://lake.example.com", token="your-token")
```

```python
lake = pondra.connect("scratch", memory_gb=2)
print(lake.sql("SELECT 1 AS one").rows())
lake.close()
```

```text
[{'one': 1}]
```

## Attributes

| Attribute | Meaning |
|---|---|
| `db.url`, `db.urls` | the node in use, and the list of every node the connection was given |
| `db.session` | the connection's session id: its temporary tables and views, and its variables, live under it |
| `db.producer`, `db.seq` | the name `append` writes under, and the sequence number of its last append |
| `db.notices` | what the last statement's procedures printed, as a list of strings |
| `db.position` | the commit a `watch` or `live` answer is as of: where to resume |
| `db.console_url` | the console in a browser, as this connection. A lake's node that `connect()` opened answers only this program, so the link carries its key (`#key=…`) and works while the node runs: keep it to yourself, as a token |

```python
print(db.urls == [db.url], db.producer.startswith("py-"), db.session != "", db.notices)
```

```text
True True True []
```

## Queries

| Method | Meaning |
|---|---|
| `db.sql(query, job=None, **names)` | a query as a frame, run when you ask for its rows. Other statements (writes, DDL, `CALL`, several at once) run now and give a `Result` or the outcome |
| `db.table(name)` | a table or view as a frame |
| `db.run(file, job=None, wait=True, **params)` | a `.sql` file on this machine, or else a `.sql`, `.py` or notebook file of the lake's, run on the node (`CALL run`, [Run files as jobs](/pondra/guides/workspace/)); or SQL text itself. The last statement's rows or outcome. `wait=False` starts a lake file's run and gives its `Run` |
| `db.from_arrow(data, name=None)` | rows of this machine as a frame: a pyarrow, pandas or Polars table, or a list of dicts. Also `from_pandas`, `from_polars`, `from_rows` |
| `db.vars` | SQL's [variables](/pondra/sql/statements/#variables): `db.vars.day` (or `db.vars["day"]`) is `$day`, `db.vars.day = date(2026, 9, 30)` sets it, `del db.vars.day` forgets it, `dict(db.vars)` has them all. `db.vars.keys()`, `db.vars.items()`, a `for` loop, `len` and `in` work too. In a procedure or a file run, they are the run's own |
| `db.parameters(file)` | a file's parameters (a SQL file's `DECLARE PARAMETER`s and the `$name`s it uses unset; a `.py` file's `# %% tags=["parameters"]` cell): name, type, default, required, description |
| `db.find(text, kind=None)` | every object, part and concept whose name, comment or definition has each word of `text`, best first, as a list of dicts: the rows of [`pondra.find`](/pondra/sql/system-tables/#parts-and-finding-things). `kind="column"` searches one kind |
| `db.save(target)` | a lake held in memory moves to `target` (a folder, or a bucket's URL) and this connection goes on over it: `ALTER DATABASE … SET LOCATION`, then the wait for the node. A move that fails raises, saying the lake stays in memory |

In `sql` and `run`, a keyword argument is a `$name` parameter in the query. A keyword whose value
is a frame, or pandas, Polars or Arrow data, is a table by that name, written `{name}` or plain.
Pondra also finds Python names in the code that called it: a DataFrame called `extra` is the table
`extra`. `job`: a write retried with the same job is applied once.

```python
db.sql("CREATE TABLE IF NOT EXISTS orders (id BIGINT, item VARCHAR, qty INT, amount DOUBLE)")
db.append("orders", [{"id": 1, "item": "tea", "qty": 2, "amount": 7.0},
                     {"id": 2, "item": "cake", "qty": 1, "amount": 4.5}])

print(db.sql("SELECT * FROM orders WHERE amount > $min ORDER BY id", min=5).rows())

import pandas as pd
extra = pd.DataFrame({"id": [3], "item": ["tea"], "qty": [1], "amount": [3.5]})
print(db.sql("INSERT INTO orders SELECT * FROM extra"))
print(db.sql("SELECT count(*) AS n FROM orders").item())
print(db.run("SELECT $x + 1 AS y", x=41).rows())
```

```text
[{'id': 1, 'item': 'tea', 'qty': 2, 'amount': 7.0}]
{'rows': 1}
3
[{'y': 42}]
```

A variable is the connection's, from SQL or from Python:

```python
db.sql("DECLARE $since DATE = DATE '2026-09-01'")
db.vars.top = 5
print(db.vars.since, db.sql("SELECT item FROM orders WHERE amount > $top ORDER BY id").rows())
print(list(db.vars.keys()), list(db.vars.items()))
```

```text
2026-09-01 [{'item': 'tea'}]
['since', 'top'] [('since', datetime.date(2026, 9, 1)), ('top', 5)]
```

A statement that writes or changes the lake returns a dict, such as `{'rows': 1}`. A query returns
a frame, and nothing runs until you call `rows()`, `collect()`, `to_pandas()`, `to_polars()`,
`item()` or `show()` on it.

## Files and other lakes

These make a frame over files, a folder, a glob (or a list of them), or another engine's table.
They are SQL's `read_*` functions: see [names](/pondra/reference/names/) for the fallbacks and
[functions](/pondra/sql/functions/#files-outside-the-lake) for the options.

| Method | Meaning |
|---|---|
| `db.read_parquet(source, hive_partitioning=None, **options)` | Parquet files |
| `db.read_csv(source, separator=None, has_header=None, hive_partitioning=None, **options)` | CSV files. Options by SQL's names (`delim=`, `header=`) work too |
| `db.read_json(source, hive_partitioning=None, **options)` | newline-delimited JSON |
| `db.read_delta(source, version=None)` | a Delta table, at its latest version or `version` |
| `db.read_iceberg(source, snapshot_id=None, version=None, allow_moved_paths=None)` | an Iceberg table: its folder or a metadata file |

`scan_parquet`, `scan_csv`, `scan_delta`, `scan_iceberg`, `scan_ndjson` and `read_ndjson` are the
same methods under Polars' names.

A path on this machine is read only by a node that `pondra.connect` opened for a lake here. A URL (`s3://`, `gs://`,
`az://`, `https://`) needs a [secret](/pondra/sql/statements/#files-and-secrets) whose scope covers
it.

```bash
printf 'id;name\n1;tea\n2;cake\n' > sales.csv
```

```python
db_files = pondra.connect("scratch")
print(db_files.read_csv("sales.csv", separator=";").rows())
db_files.close()
```

```text
[{'id': 1, 'name': 'tea'}, {'id': 2, 'name': 'cake'}]
```

The readers take the sources SQL's `read_*` functions take. `scan_*` and `read_ndjson` are the same
methods under Polars' names, and `pondra.read_*` reads through the current connection:

```python
here = pondra.connect("py-files")
here.sql("COPY (SELECT 1 AS id, 'tea' AS item) TO 'menu.parquet' (FORMAT parquet)")
here.sql("COPY (SELECT 2 AS id, 'cake' AS item) TO 'menu.json' (FORMAT json)")
here.sql("SELECT 3 AS id, 'milk' AS item").write_delta("menu_delta")
here.sql("SELECT 4 AS id, 'juice' AS item").write_iceberg("menu_iceberg")
print(here.read_parquet("menu.parquet").rows(), here.scan_parquet("menu.parquet").rows())
print(here.read_json("menu.json").rows(), here.read_ndjson("menu.json").rows(), here.scan_ndjson("menu.json").rows())
print(here.read_delta("menu_delta").rows(), here.read_iceberg("menu_iceberg").rows())
print(pondra.read_parquet("menu.parquet").rows(), pondra.current().url == here.url)
here.close()
```

```text
[{'id': 1, 'item': 'tea'}] [{'id': 1, 'item': 'tea'}]
[{'id': 2, 'item': 'cake'}] [{'id': 2, 'item': 'cake'}] [{'id': 2, 'item': 'cake'}]
[{'id': 3, 'item': 'milk'}] [{'id': 4, 'item': 'juice'}]
[{'id': 1, 'item': 'tea'}] True
```

## Writing rows

| Method | Meaning |
|---|---|
| `db.append(table, data)` | append rows exactly once: a list of dicts, or a pandas, Polars or Arrow table. A retry after a lost answer is recognised and not applied twice. Each connection numbers its appends (`db.seq`) |
| `db.write_table(name, data, mode="create")` | rows into a table: `data` is a frame, SQL text, or pandas, Polars or Arrow data (or a list of dicts). `mode` is `"create"`, `"append"` or `"overwrite"`. `"append"` is a plain `INSERT … SELECT`: into a keyed table, a key it holds is refused (`23505`), so use `db.append` (which replaces) or an upsert in SQL |
| `db.lookup(table, key)` | the current row of one key of a keyed table, or `None`. A composite key is its values, comma-separated, in the key's column order |

`append` answers with a dict. `seg` and `row` say where in the log the rows went, and `block` is the
block of row ids they were given. `duplicate` is true for a retry that was already applied, and
`conflict` is true when the write's `prev` didn't match. `ms` is the commit's time in milliseconds.

```python
print(db.write_table("orders_copy", db.table("orders")))
print(db.write_table("orders_copy", [{"id": 9, "item": "juice", "qty": 1, "amount": 2.0}], mode="append"))

db.sql("CREATE TABLE users (id BIGINT PRIMARY KEY, name VARCHAR)")
print(db.append("users", [{"id": 7, "name": "ann"}]))
print(db.lookup("users", 7), db.lookup("users", 8))

db.sql("CREATE TABLE seats (row_no BIGINT, seat VARCHAR, who VARCHAR, PRIMARY KEY (row_no, seat))")
db.append("seats", [{"row_no": 3, "seat": "B", "who": "ann"}])
print(db.lookup("seats", "3,B"))
```

```text
{'rows': 3}
{'rows': 1}
{'seg': 10, 'duplicate': False, 'conflict': False, 'row': 0, 'ms': 0, 'block': 0}
{'id': 7, 'name': 'ann'} None
{'row_no': 3, 'seat': 'B', 'who': 'ann'}
```

`from_arrow` makes a frame of rows this machine holds, and `seq` is the sequence number of the connection's
last append:

```python
import pyarrow as pa

print(db.from_arrow(pa.table({"id": [1, 2], "item": ["tea", "cake"]})).rows())
print(db.seq)
```

```text
[{'id': 1, 'item': 'tea'}, {'id': 2, 'item': 'cake'}]
3
```

## Views

`db.view(name, query, materialized=None, temporary=False, replace=None, **options)` makes a view
others read by name, and returns it as a frame. `query` is SQL or a frame.

| Argument | Meaning |
|---|---|
| `materialized=True` | keep it up to date with each new row (`CREATE MATERIALIZED VIEW`) instead of running the query when it is read |
| `temporary=True` | the view is this connection's only, until `close()` |
| `replace` | for a stored view, `False` refuses to replace one that exists |
| `**options` | the options of a materialized view: `window`, `size_secs`, `slide_secs`, `lateness_secs`, `session`, `gap_secs`, `join`, `time`, `within_secs`. See [table options](/pondra/sql/table-options/#materialized-views) |

```python
db.view("big_orders", "SELECT * FROM orders WHERE amount > 5")
spend = db.view("spend", "SELECT item, sum(qty) AS qty FROM orders GROUP BY item", materialized=True)
print(spend.sort("item").rows())
```

```text
[{'item': 'cake', 'qty': 1}, {'item': 'tea', 'qty': 3}]
```

A view made with `temporary=True` is this connection's only, until `close()`. `replace=True` makes it
again under the same name:

```python
db.view("big_temp", "SELECT * FROM orders WHERE amount > 4", temporary=True)
db.view("big_temp", "SELECT * FROM orders WHERE amount > 9", temporary=True, replace=True)
print(db.sql("SELECT count(*) AS n FROM big_temp").rows())
```

```text
[{'n': 0}]
```

## Functions and procedures

| Method | Meaning |
|---|---|
| `db.call(name, *args, wait=True, **kwargs)` | `CALL name(…)`: its rows or outcome. Arguments by position or by name. `wait=False` starts it without waiting and gives a `Run` |
| `db.create_function(name, body=None, file=None, params=None, returns=None, language="python", entry=None, vectorized=False, strict=False, volatility=None, packages=None, timeout=None, cache=None, replace=True)` | a stored function from code (or a file of it) |
| `db.create_procedure(name, body=None, file=None, params=None, language="python", entry=None, packages=None, timeout=None, replace=True)` | a stored procedure from code (or a file of it) |
| `@db.function` | a decorator: this Python function becomes one of the lake's functions, for SQL and frames, on every node |
| `@db.procedure` | a decorator: this Python function becomes a stored procedure |
| `db.task(name, sql, *, schedule=None, after=None, when=None, retries=None, retry_delay=None, timeout=None, on_failure=None, replace=True)` | [`CREATE TASK`](/pondra/sql/statements/#functions-procedures-and-tasks): `sql` run on a `schedule`, or `after` other tasks |
| `@db.task(schedule=…)` or `@db.task(after=…)` | a decorator: this Python function becomes a procedure, and a task calls it |
| `db.execute_task(name, **values)` | `EXECUTE TASK`: its graph runs now, with these values for its tasks' `$name`s; a `Run` (`.wait()`) |
| `db.secret(name)` | a secret's values as a dict; only a procedure's code may read them |
| `db.routines()` | the lake's functions and procedures, as a dict by name |

`params` maps each parameter to its SQL type, or to a pair of a type and a default. `returns` is a
SQL type, `TABLE (…)`, or a dict of column names and Python types for a table function. The
options are those of [`CREATE FUNCTION`](/pondra/sql/table-options/#functions-and-procedures).
A body is a function body, as in PL/Python; with `entry`, it is a module and the function of that
name runs.

The decorators read the function's source, so use them in a file, not at a prompt. They take the
same options as `create_function` (`@db.function(cache="10 minutes")`), and `name=` to pick another
name. The types come from the annotations. The imports, helper functions and constants the
function uses come along. A decorated function is handed back as it was, so it still runs here.

Inside a procedure, `pondra.sql(…)`, `pondra.table(…)`, `pondra.call(…)` and `pondra.secret(…)`
use the connection its caller lent it, with the caller's rights. A function has no connection:
`pondra.sql` in it raises an error, because a query may run it over millions of rows.

```bash
cat > jobs.py <<'EOF'
import re
from datetime import date
import pondra

db = pondra.connect("http://localhost:8080")
db.sql("CREATE TABLE sales (day DATE, item VARCHAR, qty INT)")
db.sql("INSERT INTO sales VALUES (DATE '2026-09-27', 'tea', 2), (DATE '2026-09-27', 'cake', 1), (DATE '2026-09-28', 'tea', 5)")

@db.function
def slug(title: str) -> str:
    return re.sub(r"[^a-z0-9]+", "-", title.lower()).strip("-")

@db.procedure
def report(day: date, top: int = 1):
    rows = pondra.sql("SELECT item, sum(qty) AS sold FROM sales WHERE day = $day GROUP BY item ORDER BY sold DESC LIMIT $top", day=day, top=top).rows()
    print(f"{day}: {len(rows)} item(s)")
    return rows

print(db.sql("SELECT slug('Hello, World!') AS s").rows())
print(slug("Hello, World!"))
print(db.call("report", date(2026, 9, 27)).rows())
print(db.notices)
EOF
python jobs.py
```

```text
[{'s': 'hello-world'}]
hello-world
2026-09-27: 1 item(s)
[{'item': 'tea', 'sold': 2}]
['2026-09-27: 1 item(s)']
```

The first `2026-09-27: 1 item(s)` line is the notice, printed as it came back. Pass `echo=False` to
`connect` to keep it in `db.notices` only.

`create_function` and `create_procedure` take code as a string:

```python
db.create_function("twice", "return x * 2", params={"x": "BIGINT"}, returns="BIGINT")
db.create_function("pairs", "return [(1, 'a'), (2, 'b')]", returns={"n": int, "s": str})
print(db.sql("SELECT twice(4) AS v").rows(), db.sql("SELECT * FROM pairs() ORDER BY n").rows())

db.sql("CREATE SECRET api (TYPE generic, token 'placeholder')")
db.create_procedure("peek", "print(sorted(pondra.secret('api')))\nreturn [{'keys': 2}]")
print(db.call("peek").rows())
```

```text
[{'v': 8}] [{'n': 1, 's': 'a'}, {'n': 2, 's': 'b'}]
['token', 'type']
[{'keys': 2}]
```

### Runs

`db.call(name, …, wait=False)` starts a procedure and returns a `Run` at once. The run's row in
`pondra.runs` says how it went.

| Member | Meaning |
|---|---|
| `run.id` | the run's id |
| `run.status()` | its row of `pondra.runs`, or a stand-in while it starts |
| `run.wait(timeout=None, every=0.2)` | poll until it ends, then give the row; raises the run's error if it failed, and `TimeoutError` after `timeout` seconds |

```python
run = db.call("peek", wait=False)
print(run.wait()["status"])
```

```text
ok
```

### Names in a Python procedure

A procedure's code also has `plpy`, PL/Python's names, so a PL/Python routine runs as it is. The
procedure's `plpy.execute` runs SQL as its caller, with the caller's rights.

| Name | Meaning |
|---|---|
| `plpy.execute(query, args=None, limit=None)` | runs SQL and gives its rows as a list of dicts, with `nrows()`, `status()` and `colnames()` |
| `plpy.prepare(query, types=None)` | a prepared statement (a `Plan`); its `execute(args, limit)` runs it with the arguments |
| `plpy.cursor(query, args=None)` | an iterator over the rows of a query |
| `plpy.notice(*msg)`, `plpy.info(*msg)`, `plpy.warning(*msg)` | a notice to the caller, as `db.notices` gets it |
| `plpy.debug(*msg)`, `plpy.log(*msg)` | to the node's standard error (its log) |
| `plpy.error(*msg)`, `plpy.fatal(*msg)` | raise `plpy.Error` or `plpy.Fatal`, failing the call |
| `plpy.Error`, `plpy.Fatal` | the exceptions `plpy.error` and `plpy.fatal` raise. `Fatal` is an `Error`, so `except plpy.Error` catches both. `plpy.SPIError` is there for code that names it; nothing here raises it |
| `plpy.quote_literal(s)`, `plpy.quote_nullable(s)`, `plpy.quote_ident(s)` | a SQL literal, a literal or `NULL`, and a SQL identifier |
| `plpy.GD` | a dict shared by every routine one worker runs |

`plpy.subtransaction()` raises `NotImplementedError`: a procedure's statements aren't nested.

```python
db.create_procedure("archive", """
rows = plpy.execute("SELECT count(*) AS n FROM orders")
plan = plpy.prepare("SELECT $1 AS doubled", ["bigint"])
doubled = plan.execute([rows[0]["n"] * 2])[0]["doubled"]
plpy.notice(f"{rows[0]['n']} orders, {rows.nrows()} row, columns {rows.colnames()}")
return [{"n": rows[0]["n"], "doubled": doubled}]
""")
print(db.call("archive").rows())
```

```text
3 orders, 1 row, columns ['n']
[{'n': 3, 'doubled': 6}]
```

`plpy.GD` is a dict that every routine one worker runs shares. `plpy.cursor` iterates over a query's rows,
`plpy.info` and `plpy.warning` send notices, `plpy.debug` writes to the node's log, `plpy.quote_*` quote text
for SQL, and `plpy.error` raises `plpy.Error`:

```python
db.create_procedure("names_demo", """
plpy.GD["seen"] = True
plpy.info("info line")
plpy.warning("warning line")
plpy.debug("debug line goes to the node's log")
first = [r["item"] for r in plpy.cursor("SELECT item FROM orders ORDER BY id")][0]
quoted = plpy.quote_literal("O'Brien") + " " + plpy.quote_ident("order items") + " " + plpy.quote_nullable(None)
try:
    plpy.error("stopped here")
except plpy.Error as e:
    caught = str(e)
return [{"first": first, "quoted": quoted, "caught": caught, "seen": plpy.GD["seen"]}]
""")
print(db.call("names_demo").rows())
print(db.notices)
print("archive" in db.routines(), "names_demo" in db.routines())
```

```text
info line
warning line
[{'first': 'tea', 'quoted': '\'O\'\'Brien\' "order items" NULL', 'caught': 'stopped here', 'seen': True}]
['info line', 'warning line']
True True
```

## Following changes

| Method | Meaning |
|---|---|
| `db.watch(table, after=None, changes=False)` | a generator of a table's new rows as they commit, one dict each. For a keyed table, every upsert and delete. `after` replays from that position first. `changes=True` also yields UPDATE's and DELETE's rows, each with `_change_type`, `_row_id` and `_version` |
| `db.live(query, every_ms=None, **params)` | a generator of a query's answer now, and again each time a commit changes it: a list of dicts each time. A busy table is queried at most every `every_ms` (default 100) |

After a row or an answer, `db.position` is where to resume. Both run until you stop them: `break`
out of the loop, or call `.close()` on the generator.

```python
for row in db.watch("orders", after=0):
    print(row)
    break

for rows in db.live("SELECT count(*) AS n FROM orders"):
    print(rows)
    break
```

```text
{'id': 1, 'item': 'tea', 'qty': 2, 'amount': 7.0}
[{'n': 3}]
```

## Results

`db.sql` of a statement that returns rows at once (a `CALL`, or a script's last query) gives a
`Result`.

| Method | Meaning |
|---|---|
| `result.rows()` | the rows, as a list of dicts |
| `result.to_arrow()`, `result.collect()` | a pyarrow Table |
| `result.to_pandas()`, `result.to_polars()` | a pandas or Polars DataFrame |

Without pyarrow installed, rows come as the node's JSON, with dates and times as text. A `Result`
has `rows()`, and so does a frame, which also has `item()` and `show()`. Tables (`collect()`,
`to_arrow()`, `to_pandas()`, `to_polars()`) need `pip install pyarrow`.

## Transactions and errors

`with db.transaction():` makes the block's statements one commit (`BEGIN` … `COMMIT`), reading its
own writes, rolled back if the block raises ([Transactions](/pondra/guides/change-rows/#transactions)).

An error from the node raises `pondra.PondraError` (a `RuntimeError`), whose `sqlstate` is
Postgres's code for it: `"23514"` a `CHECK`, `"42P01"` no such table, `"40001"` a transaction
another commit got to first (run it again). `status` is the HTTP status.

```python
db.sql("CREATE TABLE stock (sku VARCHAR, qty BIGINT CHECK (qty >= 0))")
try:
    db.sql("INSERT INTO stock VALUES ('tea', -1)")
except pondra.PondraError as e:
    print(e.sqlstate)
```

```text
23514
```

## Close

`db.close()` ends the connection's session, so its temporary tables and views go, and so do the
variables of its `DO LANGUAGE python` blocks. It also stops a lake's node once no other connection holds it. A
connection is a context manager:

```python
with pondra.connect("http://localhost:8080") as session:
    print(session.sql("SELECT 1 AS one").rows())
```

```text
[{'one': 1}]
```

`db.read_csv` takes its options by Polars' names (`separator=`, `has_header=`) or by SQL's
(`delim=`, `header=`): `db.read_csv("a.csv", delim=";", header=True)`. If you give both, Polars' win.

## Module functions

`import pondra` gives these names. The functions use the current connection: the newest one made,
or inside a procedure the one its caller lent it. Code moves between a notebook and a procedure as
it is, as `duckdb.sql` runs on DuckDB's default connection.

| Name | Meaning |
|---|---|
| `pondra.sql`, `pondra.table`, `pondra.call`, `pondra.run`, `pondra.parameters`, `pondra.secret` | the connection's methods of the same names |
| `pondra.vars` | the current connection's SQL variables: `pondra.vars.day` is `$day` |
| `pondra.read_parquet`, `pondra.read_csv`, `pondra.read_json`, `pondra.read_delta`, `pondra.read_iceberg` | the connection's readers |
| `pondra.scan_parquet`, `pondra.scan_csv`, `pondra.scan_delta`, `pondra.scan_iceberg`, `pondra.scan_ndjson`, `pondra.read_ndjson` | the same readers under Polars' names |
| `pondra.connect`, `pondra.current`, `pondra.binary` | see [Connect](#connect) |
| `pondra.col`, `pondra.lit`, `pondra.when`, `pondra.coalesce`, `pondra.concat`, `pondra.concat_str`, `pondra.sql_expr`, `pondra.all`, `pondra.len`, `pondra.sum`, `pondra.mean`, `pondra.min`, `pondra.max`, `pondra.count`, `pondra.n_unique`, `pondra.median`, `pondra.first`, `pondra.last`, `pondra.fn` | the frame functions: see [frames](/pondra/reference/frames/#expressions) |
| `pondra.Pondra`, `pondra.Frame`, `pondra.Expr`, `pondra.GroupBy`, `pondra.Result`, `pondra.Run`, `pondra.PondraError` | the classes: a connection, a frame, an expression, what `group_by` returns, a statement's rows, a started procedure, and an error from a node |
| `pondra.__version__` | the package's version |

```python
print(pondra.sql("SELECT count(*) AS n FROM orders").rows())
print("pondra", pondra.__version__)
```

```text

pondra 0.33.0
```

The module's functions work on the current connection. Aggregates and expressions are the same as a frame's:

```python
orders = db.table("orders")
orders.select(pondra.mean("amount").alias("avg"), pondra.median("amount").alias("mid"),
              pondra.max("qty").alias("most")).show()
orders.select(pondra.n_unique("item").alias("items"), pondra.first("item").alias("first_item"),
              pondra.last("item").alias("last_item")).show()
orders.select(pondra.col("id"), pondra.sql_expr("qty * 2").alias("twice"),
              pondra.coalesce(pondra.col("item"), pondra.lit("none")).alias("kind"),
              pondra.fn.upper(pondra.col("item")).alias("up")).sort("id").limit(2).show()
orders.select(pondra.col("id"),
              pondra.concat_str([pondra.col("item"), pondra.lit("!")]).alias("loud"),
              pondra.when(pondra.col("qty") > 1).then(pondra.lit("many"))
              .otherwise(pondra.lit("one")).alias("size")).sort("id").limit(2).show()
print(isinstance(pondra.col("qty"), pondra.Expr),
      isinstance(orders.group_by("item"), pondra.GroupBy))
print(pondra.current() is not None)
```

+-------+------------+-----------+
+----+-------+------+------+

+----+-------+------+------+

### The `pondra` command

`python -m pondra` runs the `pondra` binary that pip installed, with the arguments you give it, from
wherever pip put it. So it works when that folder isn't on your `PATH`. See
[install](/pondra/start/install/) for the first run.

```bash
python3 -m pondra --version
```

```text
pondra 0.33.0
```

`python -m pondra --add-to-path` puts the binary's folder on your `PATH`: in the registry on
Windows, and in your shell's startup file elsewhere (`~/.bashrc`, `~/.zshrc`, `~/.profile`). It
changes that file, so run it yourself, once. Then open a new terminal and run `pondra`.

```bash norun
python3 -m pondra --add-to-path
```
